# VTX Power Logger

Консольний застосунок для Windows, який раз на секунду зчитує середню потужність з датчика R&S NRP-Z11 і, за потреби, записує її у CSV.

## Передумови

1. Підключіть NRP-Z11 до ноутбука через сумісний USB-адаптер/кабель.
2. Встановіть **R&S NRP Toolkit** (VXI PnP driver). Драйвер надає `rsnrpz_64.dll`.
3. Встановіть Python 3.11+ для Windows. Для першого етапу інші Python-пакети не потрібні.

## Запуск

У PowerShell у каталозі проєкту:

```powershell
py .\vtx_power_logger.py --frequency-hz 2700000000
```

За замовчуванням застосунок відкриває перший доступний датчик (`--resource *`), застосовує частотну корекцію 2.7 ГГц, усереднює 16 вибірок і друкує один результат на секунду. Зупинка — `Ctrl+C`.

Запис у CSV:

```powershell
py .\vtx_power_logger.py --frequency-hz 2700000000 --csv .\logs\test-001.csv
```

CSV містить часову позначку UTC, час від початку тесту та потужність у mW. Файл дописується, тому попередні вимірювання не стираються.

## Якщо драйвер не знайдено

Передайте шлях до бібліотеки явно:

```powershell
py .\vtx_power_logger.py --dll "C:\Program Files\Rohde-Schwarz\NRP Toolkit\bin\rsnrpz_64.dll"
```

Або задайте змінну середовища `RSNRPZ_DLL` із цим шляхом.

## Пакування для закритого тестового ноутбука

На **Windows-машині розробки**, де є вихідний код і Python, виконайте:

```powershell
.\build.ps1
```

Скрипт створить `dist\VTX-Testing.zip`. Переносьте на тестовий ноутбук лише цей
архів, розпакуйте його та запускайте:

```powershell
.\VTX-Testing\VTX-MSP-Probe\VTX-MSP-Probe.exe --port COM83
.\VTX-Testing\VTX-Power-Logger\VTX-Power-Logger.exe --frequency-hz 2700000000 --csv .\logs\test.csv
```

Python, `pip`, GitHub та вихідний код на тестовому ноутбуці не потрібні. Проте
**R&S NRP Toolkit** має бути встановлений там для USB-драйвера NRP-Z11. За
потреби DLL можна додати до збірки так:

```powershell
.\build.ps1 -DriverDll "C:\Program Files\Rohde-Schwarz\NRP Toolkit\bin\rsnrpz_64.dll"
```

Це пакує DLL біля logger, але не замінює встановлення USB-драйвера.

### Передавання коду з macOS

На Mac у корені проєкту виконайте:

```zsh
./package_for_windows.sh
```

Скрипт створить `dist/VTX-Testing-source.zip` лише з потрібними для Windows
збірки файлами: Python-інструментами, `build.ps1`, `requirements.txt`,
`configs/` і README. Перенесіть цей архів на Windows, розпакуйте та виконайте
`build.ps1` за інструкцією вище.

## Обмеження першого етапу

Застосунок не керує VTX і не має GUI. Він лише вимірює та стабільно логує RF-потужність — це базова перевірка вимірювального тракту перед наступними етапами.

## Калібрування тракту

Профіль [configs/measurement_path_control.json](configs/measurement_path_control.json) містить
повний Level Offset для NRP-Z11: `30 dB` фіксованого атенюатора та частотну
поправку вимірювального тракту. Для FT VTX 2.7 (2700–3000 MHz) скрипт задає
на самому NRP-Z11 `+30.70 dB`.

Триточковий тест і повна таблиця потужності явно задають цей offset у NRP-Z11
перед кожною точкою, тому їхній результат — потужність на виході VTX. Для
проміжних частот використовується лінійна інтерполяція, поза крайніми
каліброваними частотами — найближче значення. Скрипти не додають offset вдруге
у Python.

## Перевірка VTX через Flight Controller

`vtx_msp_probe.py` лише читає поточну VTX-конфігурацію через MSP; він не змінює
налаштувань Flight Controller або VTX. Закрийте Betaflight Configurator, бо він
використовує той самий COM-порт Flight Controller.

На Windows встановіть залежність і запустіть probe. Без `--port` він перебере
доступні serial-порти та вибере єдиний Flight Controller, який відповідає на
MSP-запити:

```powershell
python -m pip install -r requirements.txt
python .\vtx_msp_probe.py
```

Якщо до ПК підключено кілька Flight Controller, скрипт виведе знайдені порти й
попросить явно вказати потрібний, наприклад `--port COM5`. Для повільних
пристроїв можна збільшити час перевірки одного порту: `--scan-timeout 2`.

Вивід містить поточні `band`, `channel`, `frequency_mhz`, `power_index` і стан
готовності VTX. Цей інструмент є безпечним першим етапом перед реалізацією
автоматичної зміни параметрів через IRC Tramp.

## Одноразовий тест A1 + вимірювання

`vtx_a1_measure.py` — інтерактивний одноточковий тест. Він показує поточний
стан VTX, пропонує обрати модель, перемикає на її A1, чекає 3 секунди,
перечитує стан через FC та лише після успішного підтвердження вимірює потужність
NRP-Z11. Поточні power index та pit mode скрипт не змінює.
Показана потужність VTX автоматично скоригована профілем вимірювального тракту;
поряд також виводиться сирий показ NRP-Z11 і застосована поправка.

Закрийте Betaflight Configurator і переконайтеся, що VTX підключений до NRP-Z11
через атенюатор. Запуск:

```powershell
python .\vtx_a1_measure.py
```

Якщо не передавати `--profile`, скрипт запропонує вибрати один із локальних
профілів VTX. Це зручно для FT VTX 5.8 і 7.2:

```powershell
python .\vtx_a1_measure.py
```

Для іншого VTX передайте відповідний профіль, наприклад:

```powershell
python .\vtx_a1_measure.py --profile .\configs\vtx_profiles\ft_vtx_2_7_4w.json
```

## Три-точковий тест FT VTX 3.3 на 4 W

`vtx_three_point_test.py` вимірює FT VTX 3.3 на B1 / 3170 MHz, A1 / 3330 MHz
та A8 / 3470 MHz у режимі 4 W. Після тесту він повертає VTX до 25 mW, зберігаючи
останню частоту. Повернення до 25 mW також виконується після помилки вимірювання,
якщо FC все ще доступний.

На кожній частоті скрипт після перемикання спостерігає потужність 3 секунди із
кроком 0.5 секунди. У терміналі він показує округлені середнє, мінімум, максимум
і зміну між першим та останнім виміром. Усі неокруглені вибірки автоматично
зберігаються у `logs/vtx-test-<UTC timestamp>.csv` — це основа для майбутнього
графіка та виявлення падіння потужності під час прогріву.

Після кожної точки показується компактна шкала `Power vs reference`: вертикальна
позначка `│` — це 100% референсного значення, а смуга та статус `OK` / `LOW` /
`FAIL` одразу показують результат. Після автоматичного тесту виводиться також
підсумкова шкала для всіх трьох частот. Тест стартує одразу після запуску —
додаткового підтвердження немає.

Перед вимірюванням скрипт у режимі read-only читає power levels польотного
контролера. Усі робочі частоти надсилаються напряму через IRC Tramp, тому
частотна VTX table FC не використовується. Скрипт не очищає VTX table та не
виконує запис у EEPROM; наприкінці потужність повертається до 25 mW.

Значення середньої, мінімальної та максимальної потужності порівнюються з
референсом конкретної точки: зелений означає не менше 90% від референсу,
жовтий — 80–89.9%, червоний — менше 80%. Пороги зберігаються у test plan в
`reference_thresholds_percent`; за потреби кольори можна вимкнути параметром
`--no-color`.

```powershell
python .\vtx_three_point_test.py
```

Скрипт запропонує вибрати 1.2 / 2.7 / 3.3 / 5.8 / 5.8.legacy / 7.2 / 8.5. Точки задаються у test plan для
кожної моделі. Поточні точки:

- FT 1.2: 1080, 1200, 1320 MHz;
- FT 2.7: 2700, 2860, 3000 MHz;
- FT 3.3: 3170, 3330, 3470 MHz;
- FT 4.8–7.2: 5695, 6870, 7210 MHz (заводська сітка 176 каналів, 4 W);
- FT 5.8 legacy: 4990, 5510, 5945 MHz (стара 64-канальна таблиця 4 W);
- FT 7.2: 6110, 6710, 7210 MHz.

Для FT 4.8–7.2 профіль містить повну заводську сітку `A`–`V` (176 каналів).
Скрипт передає потрібну частоту VTX напряму через IRC Tramp; прошивати FC
окремою таблицею для цих вимірювань не потрібно.

## Ручне перемикання тестових точок

Для ручного вибору точки додайте `--manual`. Скрипт покаже три точки обраного
test plan; введіть їхній номер, щоб перемкнути VTX на тестову потужність і
частоту. Після кожного вибору він виконує вимірювання NRP-Z11, виводить
avg/min/max та додає сирі зразки до CSV. Пункт `0` завершує сесію та автоматично
повертає VTX до 25 mW на останній вибраній частоті.

```powershell
python .\vtx_three_point_test.py --vtx 5.8 --manual
```

Для FT VTX 4.8–7.2 меню містить `M2 / 5695 MHz`, `E7 / 6870 MHz` та
`G8 / 7210 MHz`. Інші моделі показують точки зі свого test plan.

Для серії однакових VTX вкажіть модель прямо в команді — меню не з'явиться:

```powershell
python .\vtx_three_point_test.py --vtx 7.2
python .\vtx_three_point_test.py --vtx 5.8
python .\vtx_three_point_test.py --vtx 5.8.legacy
python .\vtx_three_point_test.py --vtx 3.3
python .\vtx_three_point_test.py --vtx 2.7
python .\vtx_three_point_test.py --vtx 1.2
```

## Графічний інтерфейс

Запустіть локальний GUI командою:

```powershell
python .\vtx_tester_gui.py
```

У ньому можна вибрати VTX (1.2 / 2.7 / 3.3 / 5.8 / 5.8.legacy / 7.2 / 8.5) і COM-порт, запустити three-point або повний тест,
вибрати всі рівні потужності або тільки 25 mW, 2 W чи 4 W, вказати кількість
незалежних вимірів для однієї комірки повної таблиці й настроїти затримку
стабілізації після кожного перемикання, а також
вручну задати частоту й потужність. Усі режими використовують пряме
встановлення частоти через IRC Tramp і не записують VTX table у Betaflight.
Після three-point тесту вкладка **Results** показує виміряні значення відносно
референсу: зелений `OK`, жовтий `LOW`, червоний `FAIL`.
Кнопка `🔔` у верхньому рядку вмикає/вимикає системний звук після успішного
завершення тесту; `🔕` означає, що звук вимкнений.

Кнопка **Stop** виконує м'яку зупинку: тест перериває поточний цикл, закриває
паверметр і запускає штатне повернення VTX до 25 mW. GUI показує окреме
підтвердження після отримання `Final VTX`. Закриття вікна під час активного
тесту запускає ту саму процедуру та чекає її завершення.

`vtx_power_table_measure.py` вимірює всі ненульові канали вибраного VTX на
кожному доступному рівні потужності. Результат — CSV-матриця: колонки `A1`,
`A2`, …, рядки — номінальна потужність у mW. Для кожної комірки скрипт робить
кілька незалежних вимірів і зберігає їх середнє; незаповнені slots таблиці, як
`B2…B8` у профілі 1.2 GHz, пропускаються.

```powershell
python .\vtx_power_table_measure.py --vtx 5.8 --samples 3
python .\vtx_power_table_measure.py --vtx 5.8.legacy --samples 3
```

За замовчуванням вимірюються всі доступні робочі рівні. Щоб виміряти лише один,
додайте `--power 25`, `--power 2000` або `--power 4000`:

```powershell
python .\vtx_power_table_measure.py --vtx 5.8 --power 2000 --settle-time 10
```

Режими `.all` залишаються короткими назвами для повного sweep усіх заводських
частот. Як і звичайні режими, вони використовують пряму установку частоти;
FC table потрібна лише для power levels.

```powershell
python .\vtx_power_table_measure.py --vtx 1.2.all --samples 3
python .\vtx_power_table_measure.py --vtx 2.7.all --samples 3
```

`1.2.all` проходить усі 9 частот (включно з 1258 MHz), а `2.7.all` — усі 16
частот від 2700 до 3000 MHz. Обидва режими вимірюють 25 mW, 2 W та 4 W.

### GRAPH58 P5 5.8 GHz 5 W

Для GRAPH58 P5 обирайте профіль `5.8.test` лише в режимі повної таблиці або
ручного перемикання: референсів для three-point тесту ще немає. Профіль має
64 канали `A/B/E/F/R/L/U/X` і рівні 25 mW / 500 mW / 3 W / 5 W.

```powershell
python .\vtx_power_table_measure.py --vtx 5.8.test --samples 3
```

Перед запуском завантажте універсальну power table, описану нижче.

### Універсальна таблиця для всіх VTX

Один FC можна залишити в стенді для всіх моделей. Завантажте один раз
[універсальний JSON](configs/betaflight_vtx_tables/UNIVERSAL_DIRECT_FREQUENCY_POWER_TABLE.json)
у **Video Transmitter → Load from file → Save** або вставте
[CLI-команди](configs/betaflight_cli/universal_direct_frequency_power_table.txt).

У ній лише службовий бенд `T` з 8 частотами: він не бере участі в тестах.
Тестер напряму передає VTX реальну частоту, включно з 1.2, 2.7, 4.8–7.2 та
7.2 GHz. Таблиця містить усі потрібні рівні: PIT / 25 / 500 / 2000 / 2500 /
3000 / 4000 / 5000 mW. Під час запуску тестер знаходить index потрібного
рівня за його значенням mW; відсутній рівень зупиняє тест до перемикання VTX.

### FT VTX 8.5 GHz 5 W

Профіль `8.5` має 80 частот від 7060 до 8500 MHz. Через 10 бендів частоти
встановлюються напряму через IRC Tramp; таблиця частот Betaflight не змінюється.
Повний тест проходить усі 80 частот лише на 5 W, а three-point використовує
7060, 7800 та 7980 MHz і референси з наданих вимірів.

### Старий FT VTX 5.8 GHz 4 W

Для звичайного, неширокодіапазонного VTX використовуйте окремий профіль
`5.8.legacy`. Його частоти залишаються описаними в профілі; із універсальною
таблицею їх не потрібно завантажувати у FC.

```powershell
python .\vtx_three_point_test.py --vtx 5.8.legacy
python .\vtx_power_table_measure.py --vtx 5.8.legacy --samples 3
```

Для цього профілю три точки — `X1 / 4990 MHz`, `D5 / 5510 MHz` та
`E8 / 5945 MHz`; їхні референси відповідно `3930`, `4550` і `2200 mW`.

### Повний заводський sweep FT 4.9–7.2 GHz

Для перевірки всіх заводських частот цього VTX не потрібно по черзі
завантажувати три VTX tables. Режим `5.8.all` напряму задає через IRC Tramp
кожну з 176 документованих channel-points: 22 bands `A`–`V` по 8 каналів.
Betaflight table використовується лише для power levels; її частоти та
кількість bands не змінюються.

```powershell
python .\vtx_power_table_measure.py --vtx 5.8.all --samples 3
```

На завершення VTX залишається на останній заводській частоті та повертається до
25 mW. CSV використовує `;` як роздільник і кому як десятковий роздільник, тому
у локалізованому Excel значення малої потужності не перетворюються на дати.

Для трьох нових Betaflight VTX tables 4.9–7.2 GHz використовуйте один із
профілів `low`, `mid` або `high`:

```powershell
python .\vtx_power_table_measure.py --vtx low --samples 3
python .\vtx_power_table_measure.py --vtx mid --samples 3
python .\vtx_power_table_measure.py --vtx high --samples 3
```

Перед перемиканням скрипт read-only перевіряє наявність потрібних power levels.
Частоти задаються безпосередньо; LOW вимірює 64 канали, MID та HIGH — по 56;
для кожного профілю вимірюються 25 mW, 2 W і 4 W.

За замовчуванням CSV створюється у `logs/vtx-power-table-<UTC timestamp>.csv` і
перезаписується після кожної завершеної комірки, тому вже виміряні значення не
втрачаються при перериванні. Файл має роздільник `;`, щоб одразу коректно
відкриватися в Excel із українськими регіональними налаштуваннями. Один прогрівальний
reading після кожного перемикання за замовчуванням не входить у середнє. Після
цього скрипт чекає три послідовні readings у межах 2%; якщо стабільність не
настає за 15 секунд, комірка не вимірюється й тест завершується безпечно. Потім
скрипт збирає 10 контрольних readings з інтервалом 0,5 с і виводить нейтральний
статус `rising`, `falling` або `stable`. `rising` / `falling` означає, що перший
і останній контрольні покази відрізнилися більш ніж на 2%; це інформація про
дрейф, а не помилка тесту. Перед запуском скрипт тільки читає й перевіряє VTX
table; він не записує table або EEPROM. Під час вимірювання змінюються лише
поточні частота та power index, а наприкінці VTX повертається до 25 mW.

Точки та power index зберігаються у відповідному файлі `configs/test_plans/`.
Еталонні потужності мають єдине джерело у `configs/reference_measurements/` і
підставляються у точки під час завантаження test plan. Пороги кольорів і статусів
задаються в `reference_thresholds_percent` цього test plan.
